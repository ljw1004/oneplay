# M23 plan: Expand the player when listening

## Summary

Make the current player drawer follow deliberate Play, browsing and natural playback stops in the hosted PWA and bundled iOS app. Learn the listener’s preference from the existing open and close gestures. Restore the drawer offline and keep the now-playing indicator in sight when expansion would cover it. Verify both preference paths, geometry and lifecycle behavior in the browser and on iOS.

## Locked user decisions

- Keep the current drawer and mode control. The internal `autoExpand` preference defaults to true. An explicit drawer open sets it true and an explicit drawer close sets it false. A listener who opens the drawer to change mode can close it afterward to get compact starts again. The owner accepts that opening sets the preference immediately.
- Keep the preference through automatic layout changes. Deliberate Play opens the drawer when the preference is on. Browsing and a natural stop collapse it. Restore both the preference and actual drawer layout on reopen.
- On a manual or automatic opening, keep the current folder. If the drawer covers its previously visible playing chevron and there is room, scroll only as far as needed to reveal that indicator. The scroll leaves the drawer open. [Listener design](DESIGN.md#when-the-player-expands-and-collapses)

## PLAN

### Listener interactions

Use the current compact footer (playing indicator, title, Play/Pause) and the current expanded drawer (gripper, mode label, wheel and footer). Keep existing copy, errors and retries. A compact listener can tap the gripper or swipe up, tap the mode label, then close with the gripper, downward drawer swipe or a tap on the empty drawer area. The next track tap stays compact. With auto-expand on, a track tap, folder Play or footer Play/Resume opens the drawer when a playable target is admitted. A Search track result follows its existing route into the folder, then counts as a track tap. Use the selected target's indicator, including its loading spinner, if it is already in view.

While the drawer is open, a vertical folder-list scroll, folder or breadcrumb navigation, or opening Search, Settings or Select returns room to the list. The same gesture carries out its normal action while audio keeps playing. A natural stop closes the drawer even when the listener stays put. One, the last playable entry in All, end-of-track Timer, and a numeric Timer expiry are stopping points. Manual Pause, automatic advance, a seek that keeps playback active, buffering, audio interruption and system Resume leave the layout alone. If an existing seek-to-end or skip-to-end path applies normal end-of-track policy and actually finishes playback, it follows that stop. After a stop the listener can reopen the wheel to change mode.

An empty or known-unplayable selection keeps its existing feedback and does not open the drawer. An admitted selection can show the drawer while audio is loading. Existing errors and retries remain usable if media loading later fails. Give any subsequent browse or manual drawer action precedence over expansion from a pending Play. A live page returning from lock collapses on a newly observed natural stop, including when system Play resumed audio before wake. A fresh document restores its saved layout when its first usable playback state arrives. A paused cold restore keeps audio paused and uses that layout. A replacement document uses the last saved layout as its baseline if the old view missed a stop.

### Shared drawer and view state

- Keep one drawer policy in the shared TypeScript UI. Route manual drawer gestures, accepted foreground Play, automatic close and view restore through its existing expansion setter. Only the manual path writes preference. An already-open Play and already-closed collapse are idempotent. On collapse, cancel an active scrub through the existing gesture cleanup before making the panel inert. This releases capture and discards a late release that could otherwise resume audio after Timer. Keep the existing time update and native debug refresh after actual layout changes. Split native Debug height recalculation and subscription refresh from the setter so it cannot look like user intent or scroll the list.
- Extend the existing profile-scoped view record in `src/index.ts` to `{path, expanded, autoExpand}`. Load each valid boolean synchronously, defaulting to compact and true respectively. Seed the shared UI's two values directly from the record. An early path save carries both values through unchanged. Use one persistence path for changes to the selected path or either drawer value. Honor existing personal sign-out cleanup and Demo retention. Storage write failure leaves the in-memory layout functional. No new stores or settings screens.
- Keep the footer hidden while it has no target. When the browser restore or the first usable native sample supplies restored playback, draw the current layout without animation or marker reveal. If the first target comes from an admitted foreground Play, publish its indicator and use the deliberate opening and reveal path, including when the saved drawer value was open. If the listener began browsing while restored playback was still pending, the shared drawer state already contains and saves their compact layout. Preserve the tree's existing scroll restoration and Select exclusivity.
- Use one drawer action revision for pending explicit Play. Capture it at the foreground Play action. Invalidate older requests on browsing, a manual drawer gesture, or a superseding foreground playback action. Keep the existing playback selection and command checks and recheck the drawer revision immediately before opening. Pending media and bridge operations still finish as usual. A natural stop collapses the drawer while leaving a pending Play for a different selection eligible.
- Make the current gripper a button with an accessible name and `aria-expanded`, preserving its visual design and gestures. Provide a 44 px touch target within the player, clear of its other controls. Set the collapsed wheel and mode controls inert. If collapse hides the focused control and the footer stays visible, focus the gripper without scrolling. Use the existing full-height landscape condition to make the covered tree and Settings inert while retaining their layout and honoring any other interaction lock. Move covered focus to the gripper before applying inert, both on drawer opening and on rotation with the drawer open. Collapse or rotation restores normal navigation as soon as the view is uncovered. Preserve visible focus and the established focus paths for Search, Select and Settings.

### Playback boundaries

- In `src/playback.ts`, use the admitted target in the explicit selection path and the footer's accepted Play/Resume branch. If Resume needs to reload audio for a retained target, pass its request through the same eligibility gate as a new selection. Present the target and publish its list indicator before opening. Preserve the audio element’s current gesture timing and queue selection. Wire the shared close to the terminal outcomes of `handleNaturalEnd` and the actual Timer pause path. Keep the fast automatic handoff and its existing error behavior.
- In `src/native-playback.ts`, use the committed foreground `start` or applied footer `play` reply after painting. Qualify the initiating action with the existing generation and target checks. In Swift, return the session, target revision and latest natural-stop ID from the same lock acquisition that accepts Play. Include those values in the existing bridge reply alongside its usual live snapshot. `LibraryController.swift` samples that snapshot after awaiting checkpoint writes. By then a remote command, automatic advance or a natural stop can have changed what is playing. Compare the accepted values with the latest sequence-gated snapshot. Expand if that session and target revision are still starting or playing and their stop ID is unchanged. These identities survive automatic track advance. A stopped or superseded play leaves the drawer compact. Legacy migration, periodic snapshots and remote commands carry no expansion request.
- In `music/ios/App/NativePlayback.swift`, give the existing playback snapshot the latest natural-stop ID from the live player. Issue it at confirmed natural completion or a live numeric Timer expiry, including when existing Play/seek-to-end policy actually stops. Route an edit-fenced end through the existing deferred queue decision and issue the ID only if that boundary really stops. Cancellation, unreadable recording progression, manual pauses, paused seeks and source revocation keep their existing states. A generic `ended` or `paused` value has several causes. Retain the latest ID across an ordinary run replacement or remote Resume so a suspended view can learn about the stop on wake. Include it when a finished held track has no row. The first accepted snapshot establishes the document's baseline. Later sequence-gated paints collapse once per newly observed ID. Keep only the latest ID in memory and leave playback checkpoints untouched.

## BETTER ENGINEERING INSIGHTS + BACKLOG ADDITIONS

- The browser already persists drawer layout but obtains it by reading a CSS class at path-write time. Native uses the same drawer without sharing this persistence. Make the shared UI report its own state and let the existing view record persist it. The tree owns scroll geometry and gesture detection, and the two playback engines report the end of a listening run where they already decide it. This removes the need for a parallel drawer state machine or for the view to infer a queue stop from media/UI state.
- Capture the cause at the input or playback boundary. An ordinary scroll report and a paused/ended transport snapshot are useful for rendering and persistence, but each can also be produced by several unrelated paths. The milestone needs narrow provenance at those boundaries. No separate prerequisite milestone is identified.
- Browser media can report `timeupdate` and `pause` after changing `paused` and before dispatching `ended`. A numeric Timer expiry at this boundary lets `ended` decide whether the queue should advance. Every terminal branch clears the old deadline so replay gets a fresh interval.
- A native start can publish its first target before its bridge reply. Keep the first visible layout compact until that admission settles. Restore saved layout on rejection when there is an existing target. When a committed first Play is superseded, persist the compact layout the listener actually saw.
- Swift identifies the session the current document actually started. WebKit consumes that origin at the session’s first visible target. A legacy restore after rejected Play still uses the saved layout. If a fenced held track briefly disappears and its session then advances, the existing layout returns without changing the preference.
- The portrait gripper needed another seven pixels of clearance above the wheel. Both browser engines hit the gripper at the top of the interactive ring before the change. Landscape coverage now composes with the tree's sign-out lock while Settings can recover independently from a failed sign-out.

## USER VALIDATION SUGGESTIONS

1. Tap a song near the bottom of a long folder. The wheel opens and the playing indicator stays in view. Scroll the list or tap a breadcrumb. The drawer closes and playback continues. Start another song or press Play to bring it back.
2. Close the drawer by hand, then start another song. Only the compact footer appears. Open the drawer to change mode and close it again. Future Play stays compact. Open the drawer and leave it open to turn auto-expand back on.
3. Choose **One** and let the song finish. The drawer closes by itself. Open it to change mode. It stays open until the next applicable gesture or playback stop.
4. While the drawer is open, close and reopen OnePlay. The same layout returns when the track is restored. Repeat after a browsing collapse. The app reopens compact and Play opens the drawer again. Open the drawer in landscape and rotate back to portrait. The wheel adapts, and opening while the drawer fills the landscape screen issues no reveal scroll.
