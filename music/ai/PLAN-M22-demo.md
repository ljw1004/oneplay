# M22 plan: Offer the demo music library

## Summary

Publish a small versioned music catalog from `oneplay-test` and open it without a sign-in or scan in the hosted PWA and bundled iOS app. Reuse the existing library, player and offline controls. Keep demo activity on this device and give listeners a direct path from Settings to their own OneDrive library. Verify the public catalog, cached startup, playback under lock and profile isolation. The startup recovery work in [PLAN-M21-lock](PLAN-M21-lock.md) is the baseline for this plan.

## Locked user decisions

- At first launch and after explicit sign-out from either provider, offer the two choices shown below. Demo is public and opens without a sign-in or indexing scan. App Review uses the same route.
- On the demo tree, the Settings control shows a warning indicator to direct listeners there. Demo Settings explains how to return to the provider chooser and offers **Sign out of Demo**. OneDrive is the personal provider available in this milestone.
- Use the public, noncommercial `oneplay-test` music collection. Provide the published credits. The manifest format and its publishing workflow are part of this plan. Build and publish them during implementation.
- Demo favorites, playlists and downloads are device-local and isolated from the OneDrive library. The hosted PWA and bundled iOS app both support Demo. The OneDrive index format and cache algorithm require separate owner signoff for any change.

## PLAN

### 1. Publish the catalog

Keep the generator and `.github/workflows/publish-demo-music.yml` in the [oneplay-test media repository](https://github.com/ljw1004/oneplay-test). Commit those two source files there during implementation. Publish the generated manifest as a Pages artifact. Use `https://ljw1004.github.io/oneplay-test/music/index.json` as the stable endpoint.

```json
{
  "schemaVersion": 1,
  "mediaCommit": "3c27e63f30508e51367fda110153f48936eb9b37",
  "tracks": [
    {
      "path": "Audiobooks/Alice's Adventures in Wonderland/01. Down the Rabbit Hole.mp3",
      "bytes": 6416949,
      "blob": "51dce49ac2daa1510958c942033c2a6abf34800e"
    }
  ]
}
```

- The UTF-8 catalog describes one complete, nonempty `Music/` snapshot. A path is the original unescaped path relative to `Music/`. Preserve case and Unicode. Each row has a unique relative path ending in `.mp3` case-insensitively, a positive safe-integer byte length and the full lowercase Git blob SHA. The commit and blob IDs are 40 hex characters. Derive folders, titles and counts from paths. Sort publication rows by path with a locale-independent comparison. The app still uses its existing sort for display.
- Derive URLs from the fixed raw HTTPS host, owner, repository and the manifest's commit. Use one RFC 3986 encoding rule in both languages. Encode each segment's UTF-8 bytes outside `A–Z a–z 0–9 - . _ ~` as uppercase percent escapes and use literal slashes between segments. The credits link points to `credits.txt` at the same commit. Each addition or change ships with the source, license, attribution and changes recorded in credits. The publisher checks that a nonempty credits file is present. Catalog curation owns the accuracy and completeness of attribution.
- The workflow runs on `main` pushes affecting `Music/**`, `credits.txt`, the generator, or the workflow, with manual dispatch from `main`. Serialize publication and resolve current `main` once within the workflow's concurrency group. The generator and every API read use that commit. Read the commit's root Git tree, then the recursive `Music` subtree with the Git Trees API. A sparse checkout of the generator suffices. Include ordinary tracked MP3 files and skip other file types, symlinks and submodules. Git LFS pointers are unsupported in `Music/`. Inspect MP3 blobs below 1,024 bytes for the Git LFS pointer header and fail if one is found. Fail before deploying for an incomplete listing, no eligible MP3s, or invalid track data. A clean input commit yields deterministic JSON. The first deployment verifies real raw MP3 bytes and matching total lengths with two representative range requests. [Git LFS pointer specification](https://github.com/git-lfs/git-lfs/blob/main/docs/spec.md#the-pointer)
- Enable Pages with **GitHub Actions** as the publishing source. Upload only `music/index.json` from a read-only build. Deploy in the `github-pages` environment with Pages publish permissions. Keep the last successful publication available on a failed build and keep published media commits reachable from `main` so saved manifests still resolve their audio. Verify that the stable URL returns JSON and is readable by browser fetch from the hosted app's origin. The first successful publication is the prerequisite for connecting the app to production Demo. [Git Trees API](https://docs.github.com/en/rest/git/trees#get-a-tree) · [GitHub Pages custom workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) · [Commit-pinned file links](https://docs.github.com/en/repositories/working-with-files/using-files/getting-permanent-links-to-files)

### 3. Compose one library at a time

**Profile admission and storage.** Choose the profile before opening its library state. One document composes one profile. While the chooser is active, a single open attempt may read, fetch and atomically save only the isolated demo catalog. When the current attempt has a valid snapshot, save the local Demo selection and admit the Demo profile. On the first switch, retire the chooser document and open the Demo document with its own stores. An attempt superseded by Connect cannot write the selection or switch profiles. The chooser stays available during this preparation. Keep the hosted service worker registration before the startup branches.

- Browser Demo uses a separate IndexedDB database with the existing data and audio stores. Keep the Demo selection and library-specific storage keys outside the `oneplay_music_` sign-out prefix. Bind the scoped operations once when wiring favorites, bookmarks, offline state and playback. OneDrive keeps its existing stores, keys and PKCE tokens. Process the existing OAuth callback before startup admission. Successfully saved personal credentials take precedence over the Demo selection, which is cleared on success. Recheck the active profile and attempt on `pageshow` after OAuth Back or history restore. A restored page whose profile has changed reloads before its commands can run. Preserve the initiating screen only for the connection attempt.
- Bundled Demo uses a second persistent `WKWebsiteDataStore` for page state and a `PlaybackStore` under a separate fixed Application Support root, a sibling of personal `Playback/`. Its native store holds the catalog, queue, bookmarks, pin manifest and completed recordings. Personal cleanup explicitly targets the fixed personal WebKit store and personal playback root. Swift completes pending personal cleanup before admission. Keep one live native player, offline worker and background session identifier. The player stays live across WebContent replacement. A profile switch may create a fresh player using the same construction path. A cold process restores playback paused.
- A verified native pairing is the durable commit for entering OneDrive from the chooser, even if the initiating WebKit document is replaced before its reply. Cancellation or failure before commit leaves the chooser available. Demo has already closed before the listener starts a OneDrive connection. At restart, a committed pairing takes precedence over the Demo selection. Clear the selection during personal sign-out cleanup before removing the pairing. When leaving Demo, park the player at its live anchor, checkpoint and wait for the existing writer before draining and rebinding. Use the last durable checkpoint if writing fails and log the failure. Cancel incomplete Demo transfers on switch. Requeue missing recordings from saved pin intent on re-entry. Keep committed Demo files.

- Keep the theme as a device preference. In the bundle, persist changes in the existing device theme file and apply its value at document opening, including over a stale profile value. Fall back to the existing stored theme until the device file is available. Timer and library-specific controls use the active profile's settings.
- Make remote documents an optional favorites dependency. Demo uses the existing local save, notification and heal paths with no cloud read or write. Compose OneDrive's share loader, source proofs and pull coordinator for the personal library. Share the tree installation and physical traversal through an explicit walkable Demo root with `demo` as its root key and its current `driveId` field. Pass a `MusicFolder` projection to the shared tree. `MusicData` and its Graph metadata stay with OneDrive's index. Use the walkable root for browse, search, selection, pins and queues. New Demo references carry the explicit source root key, and legacy OneDrive reference fallback stays account-only. A lone demo source gets the same home expansion as a sole OneDrive root.

**Snapshot admission.** Browsers fetch the fixed manifest directly without credentials and persist it in the demo database. Bundled iOS fetches the same URL without credentials in Swift. Swift restores the committed manifest before adopting saved pin transfers and makes it available to the bundled page through a narrow demo catalog read and refresh bridge. The page projects the same manifest shape to `MusicFolder`. Native media resolution is available even before a WebView opens. Extend the existing native playback and pins admission checks to use the selected workspace while keeping Graph transport and source proofs account-bound. The demo bridge exposes no general network transport and accepts no playback URLs from JS.

- Validate structure and version, lowercase commit and blob IDs, positive safe-integer byte lengths, and paths before committing a snapshot. The generator and app validators reject empty, dot and dot-dot path segments, backslashes, invalid Unicode, duplicate paths, file/folder conflicts and canonically equivalent sibling aliases. Preserve accepted names byte-for-byte. Use null-prototype child maps for the browser projection. Test paths containing spaces, Unicode, and literal percent, apostrophe, hash, question mark and colon characters with shared expected encodings.
- Commit the complete validated snapshot atomically before swapping the tree or media lookup. Coalesce startup and recovery checks. Native refresh, durable writes, media resolution and background pin transfers belong to the active profile. Existing document admission owns bridge commands and replies. A WebKit replacement can read an already committed refresh result and rejoin an in-flight native request. Retiring the profile invalidates pending work. In the browser the profile and document lifetimes coincide. A rejected or unreachable manifest or a failed commit leaves the last complete snapshot in use. Retry automatically. Keep a failed local read distinct from a confirmed cache miss.
- On cached startup, publish local state and then check for a newer release in the background. On reconnect or visibility return, recover a failed check and resume pending downloads. Use the same local HTTP revalidation policy for startup and recovery. A successful unchanged response keeps the old tree and playback state. A valid replacement reuses the existing tree, favorite healing, queue reconciliation and pin projection. Heal against a complete committed tree only. Keep downloads accessible during a refresh, with later media requests resolved against the admitted snapshot.
- Derive Demo reachability from the current route and its own request outcomes. Map reachable, unknown and offline states to the existing download gates and provider-appropriate UI language. Allow user-initiated streaming while reachability is unknown, and keep cached playback throughout. Use the existing offline controls with no OneDrive auth wording. Where HTTP status is observable, a media 404 or 410 marks that item unavailable. A transport error, throttling or other service failure enters bounded automatic retry. A successful catalog check does not erase download backoff for a failing media request. Playback through HTML audio uses its existing media-error behavior. A failed catalog check leaves cached browsing and playback usable.

**Recording identity and playback.** A folder ID is `folder-` plus the escaped relative directory path, with an empty path for the root. A track ID is the blob SHA, a literal hyphen, and the escaped path using the rule above with slashes as delimiters. IDs contain no colons, so the existing `driveId:itemId` keys can be reused. Unrelated releases keep IDs and downloaded files. Same-path replacements update the ID and fetch the new bytes even if the length is the same. Favorites can heal the same path. A rename is a remove and add in v1. Keep duplicate recordings at different paths as distinct entries.

- In the browser, implement the existing `BrowserMedia` contract. Return the derived immutable URL without an expiry or metadata request and let the player prewarm its synchronous successor as usual. Download a complete Blob with the declared length before publishing it. Use the known MP3 media type for the offline Blob if the raw response gives a generic type.
- In Swift, the player and pin worker resolve the admitted demo item locally to the raw URL, size and blob version. Reuse the native range reader, decoder and background pin session. Its HTTP range validator comes from the actual raw response. Keep existing metered-route behavior, pin completion checks, source admission, lock-screen handoff and interrupted audio policies. Under ordinary catalog refresh the playing decoder can finish from its admitted media or leased pin. Queue changes use existing reconciliation. New reads for a removed or replaced ID cannot resolve to different bytes.
- Close the retiring profile’s admission before rebinding. Qualify native play and pin requests by the active source, and accept Demo media IDs only from the admitted catalog. Reset worker reachability on a profile switch. Restore the native profile and its durable manifest before binding pin inventory or adopting transfers under the existing tickets.
